## 一、项目概览

| 属性 | 说明 |
|------|------|
| **产品名称** | 食记（ShiJi） |
| **产品定位** | AI 驱动的饮食记录 App + 基础健康数据看板 |
| **平台** | Android 8.0+（Material 3） |
| **目标用户** | 20-40 岁健康意识人群，健身爱好者，AI 技术用户 |
| **核心差异化** | 用户自持 AI API Key，拍照识别食物热量；纯本地存储，隐私可控 |

---

## 二、品牌标识

- **App 名称**：食记
- **品牌关键词**：健康、简洁、智能、可信
- **品牌色**：健康绿 `#4CAF50`
- **品牌气质**：现代简约 + 轻量科技感，不过度设计，让功能说话
- **对标产品**：MyFitnessPal（功能参考）、Notion（简洁感参考）

---

## 三、设计理念

```
简洁 · 高效 · 智能 · 可信
```

| 原则 | 含义 | 设计体现 |
|------|------|----------|
| **简洁** | 界面干净，减少认知负荷 | 一屏一任务，避免信息堆砌；大量留白 |
| **高效** | 最少步骤完成任务 | 首页直达三大记录入口（拍照/语音/手动），< 3 步完成一次饮食记录 |
| **智能** | AI 自然融入流程 | AI 是辅助工具而非主角；用户始终有最终编辑权 |
| **可信** | 用户掌控数据与 AI | API Key 归属感、数据本地化标识、透明用量展示 |

**交互行为**：
- 热量圆环：进入页面时从 0 动画到当前值（800ms，缓出曲线）
- 点击圆环 → 跳转数据 Tab 热量详情
- 点击快捷入口 → 进入对应记录流程
- 点击饮食列表项 → 编辑该记录
- 左滑列表项 → 显示删除按钮
- 点击"查看全部" → 跳转完整饮食日志

## 十二、核心交互流程

### 流程 1：拍照识食（完整路径）

```
首页 [📸拍照] → 相机取景 → 拍照 → 图片预览 [使用照片]
→ AI 分析中 (Loading 动画，3-8s)
→ 结果确认页（可编辑每项食物、调整份量、选择餐次）
→ [确认保存] → 完成动画 ✓ → 返回首页
```

**异常路径**：
- AI 超时（15s）→ 弹窗"是否继续等待" → [继续等待] / [手动输入]
- AI 解析失败 → 显示原始文本 + 降级为手动输入
- 非食物图片 → 提示"未识别到食物，请重新拍摄"
- 单项识别错误 → 该项可点击编辑 / 删除

### 流程 2：语音记录

```
首页 [🎤语音] → 按住说话 (实时波形 + ASR 文字上屏) → 松开发送
→ AI 解析中 (2-5s)
→ 结果确认页（同拍照流程）
→ [确认保存] → 返回首页
```

### 流程 3：手动添加

```
首页 [✏️手动] → 搜索食物（可选，匹配本地食物库）
→ 填写详情（食物名称 + 份量 + 单位）
→ [保存] → 返回首页
```

## 十四、微交互定义

| 交互 | 触发条件 | 表现 | 时长 |
|------|----------|------|:--:|
| **记录成功** | 确认保存饮食记录 | 按钮出现 ✓ → 缩放+绿色脉冲 → 自动返回 | 600ms |
| **热量圆环动画** | 进入首页 / 数据更新 | 圆环从 0 平滑过渡到当前值 | 800ms 缓出 |
| **AI 分析指示器** | 等待 AI API 返回 | 三颗跳动点 ●●●，颜色渐变流动 | 持续至返回 |
| **语音波纹** | 按住录音按钮 | 圆形波纹从按钮中心向外扩散，振幅随音量变化 | 持续至松手 |
| **点击反馈** | 点击任何可交互元素 | 元素缩放到 96% → 回弹 | 100ms |
| **列表项滑出** | 左滑列表项 | 平滑滑出，右侧显示删除按钮 | 200ms |
| **主题切换** | 切换深色模式 | 颜色平滑过渡 | 300ms 淡入淡出 |

## 十五、深色模式适配要点

1. 所有页面必须有对应的 Dark Theme
2. 背景色从 `#FAFAFA` → `#121212`，卡片从 `#FFFFFF` → `#1C1B1F`
3. 绿色主色在暗色背景下亮度适当提高（`#4CAF50` → `#81C784`）
4. 文字对比度在暗色模式下仍需满足 WCAG AA 标准
5. 图标在暗色背景下使用浅色变体
6. 阴影在暗色背景下调整为发光效果代替（elevation overlay）
