# 🎨 02 — 产品设计文档

> 版本：v2.0 | 日期：2026-06-25 | 状态：已校准

**产品名称**：食记

---

## 1. 设计原则

### 1.1 核心设计理念

```
简洁 · 高效 · 智能 · 可信
```

| 原则 | 含义 | 设计体现 |
|------|------|----------|
| **简洁** | 界面干净，减少认知负荷 | 一屏一任务，避免信息堆砌 |
| **高效** | 最少步骤完成任务 | 首页直达记录入口，<3 步完成饮食记录 |
| **智能** | AI 能力自然融入流程 | AI 是辅助工具而非主角，用户始终拥有最终决定权 |
| **可信** | 用户掌控数据和 AI | API Key 归属感、数据本地化标识、透明用量展示 |

### 1.2 设计语言

- 风格定位：**现代简约 + 轻量科技感**
- 色彩基调：健康绿 + 中性灰（见第 4 节）
- 字体：系统默认（中文 Noto Sans SC / 英文 Roboto）
- 圆角：大圆角卡片（16dp），柔和友好
- 动效：微交互（点击缩放 96%、列表项自然过渡）

## 3. 核心交互流程

### 3.1 拍照识食 — 完整流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  相机界面  │ →  │ 图片预览   │ →  │ AI 分析中 │ →  │ 结果确认  │ →  │ 记录完成  │
│  拍照/选图 │    │ 裁剪/重拍  │    │ 进度动画  │    │ 编辑修正  │    │ 返回首页  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
     ↑                              │                                  │
     └──────── 取消/重拍 ──────────┘                                  │
                                      └──── 分析失败 → 手动输入 ──────┘
```

#### 步骤详解

**Step 1 — 相机界面**
- 启动 CameraX 预览，全屏取景
- 顶部：闪光灯开关、网格辅助线
- 底部：拍照按钮（大圆形）+ 相册入口
- 拍照后震动反馈

**Step 2 — 图片预览**
- 显示拍摄/选中的照片
- 操作栏：[重拍] [使用照片]
- 可选：裁剪、旋转
- 点击"使用照片" → 触发 AI 分析

**Step 3 — AI 分析中**
- 全屏 Loading 状态，使用骨架屏/脉冲动画
- 提示文字：`正在分析食物...`
- 预计耗时：3-8 秒（取决于模型和网络）
- 可取消（回到预览界面）

**Step 4 — 结果确认**
- 顶部：食物缩略图（可点开查看大图）
- 中部：AI 识别结果列表，每项显示：
  - 食物名称（可编辑）
  - 估算份量（可调整 + / - 按钮）
  - 估算热量（自动计算，也可手动修正）
  - 宏量营养素（蛋白质/碳水/脂肪）
- 底部：餐次选择（早餐/午餐/晚餐/加餐）+ 日期
- Action：[取消] [确认保存]

**Step 5 — 记录完成**
- 简短的完成动画（✓）
- 自动返回首页，饮食列表刷新

### 3.2 语音口述记录 — 完整流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  录音界面  │ →  │ AI 解析中 │ →  │ 结果确认  │ →  │ 记录完成  │
│  按住说话  │    │          │    │ (同拍照)  │    │          │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

#### 步骤详解

**Step 1 — 录音界面**
- 大面积录音按钮（按住说话，松开发送）
- 实时声波动画（录音中）
- 文字实时上屏（ASR 结果流式显示）
- 最长 60 秒，超时自动停止
- 松手后 1 秒内可取消（上滑取消手势）

**Step 2 — AI 解析中**
- 显示已识别的文字
- Loading 动画：`正在解析食物信息...`
- 预计耗时：2-5 秒

**Step 3 & 4** — 同拍照流程

### 3.3 手动添加食物

## 4. UI 设计规范

### 4.1 色彩系统

```css
/* 主色调 — 健康绿 */
--primary:        #4CAF50   /* 主色 */
--primary-dark:   #388E3C   /* 深色变体 */

--on-primary:     #FFFFFF   /* 主色上的文字 */

/* 功能色 */
--calories:       #FF6D00   /* 热量相关 */

--fat:            #2196F3   /* 脂肪 */
--success:        #4CAF50   /* 成功/达标 */
--warning:        #FF9800   /* 警告/接近上限 */
--error:          #F44336   /* 错误/超标 */

/* 中性色 (Light Theme) */
--surface:         #FFFFFF
--surface-variant: #F5F5F5
--background:      #FAFAFA
--on-surface:      #1C1B1F
--on-surface-variant: #49454F
--outline:         #79747E

/* 中性色 (Dark Theme) */
--surface-dark:         #1C1B1F
--surface-variant-dark: #2B2930
--background-dark:      #121212
--on-surface-dark:      #E6E1E5
```

### 4.2 字体排版（Type Scale）

| 用途 | 字号 (sp) | 字重 | 行高 |
|------|-----------|------|------|
| Display（大标题） | 32 | Bold 700 | 40 |
| Headline（标题） | 24 | SemiBold 600 | 32 |
| Title（小标题） | 20 | SemiBold 600 | 28 |
| Body Large | 16 | Regular 400 | 24 |
| Body Medium | 14 | Regular 400 | 20 |
| Body Small | 12 | Regular 400 | 16 |
| Label | 11 | Medium 500 | 16 |

### 4.3 间距系统

采用 4dp 栅格系统：

| Token | 值 (dp) | 用途 |
|-------|---------|------|
| xs | 4 | 紧凑间距 |
| sm | 8 | 组件内部间距 |
| md | 16 | 标准边距、卡片 padding |
| lg | 24 | 区块间距 |
| xl | 32 | 大区块间距 |
| 2xl | 48 | 页面级间距 |

### 4.4 阴影（Elevation）

| Level | 用途 |
|-------|------|
| 0dp | 平面内容 |
| 1dp | 卡片、列表项 |
| 2dp | FAB 按钮 |
| 3dp | 底部弹窗 |
| 6dp | 对话框 |
| 8dp | 顶部栏（滚动时） |

### 4.5 圆角

| Token | 值 (dp) | 用途 |
|-------|---------|------|
| sm | 8 | 小按钮、Chip |
| md | 12 | 输入框、小卡片 |
| lg | 16 | 标准卡片、面板 |
| xl | 24 | 大卡片、弹窗 |
| full | 9999 | 胶囊按钮、头像 |

## 6. 微交互定义

### 6.1 记录成功反馈
- 触发：用户确认保存饮食记录
- 表现：按钮出现 ✓ 图标 → 缩放+绿色脉冲 → 页面自动返回
- 时长：600ms

### 6.2 热量圆环动画
- 触发：进入首页 / 数据更新
- 表现：圆环从 0 平滑过渡到当前值
- 时长：800ms，缓出曲线

### 6.3 AI 生成中指示器
- 触发：等待 AI API 返回
- 表现：三颗跳动的点（●●●），颜色渐变流动
- 文字：`AI 正在分析中...`

### 6.4 语音录音波纹
- 触发：按住录音按钮
- 表现：圆形波纹从按钮中心向外扩散，振幅随音量变化
- 颜色：主色 #4CAF50

## 7. 原型与可用性测试计划

### 7.1 原型阶段
- 使用 Figma 制作高保真原型
- 覆盖 5 个核心流程：拍照识食、语音记录、手动添加、API 配置、AI 对话

### 7.2 可用性测试
- 招募 5-8 名目标用户
- 任务测试（Moderated Usability Testing）
- 关键指标：
  - 首次配置 API Key 耗时（目标 ≤ 3 分钟）
  - 完成一次拍照识食耗时（目标 ≤ 30 秒含拍照和确认）
  - 任务完成率（目标 ≥ 90%）
